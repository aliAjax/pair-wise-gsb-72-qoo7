# 功能开关灰度发布与影响审阅平台

基于 React 的本地可运行前端工程，覆盖功能开关配置、影响评审、依赖分析、灰度时间线、冻结回滚和发布报告。业务数据由 RTK Query 端点驱动，并持久化到浏览器 `localStorage`。

## 技术栈

- React 18 + TypeScript + Vite
- MUI
- Redux Toolkit
- RTK Query
- React Router

## 启动

```bash
npm install
npm run dev
```

默认开发地址为 `http://localhost:18472`。

## 构建

```bash
npm run build
npm run preview
```

## 工作区

- 发布概览：开关采用趋势、环境放量差异、阻断问题和待评审项
- 功能开关：按状态、环境、团队和关键字筛选，多选后批量冻结、批量回滚或批量补监控
- 影响评审：逐项检查规则冲突、死代码、指标缺失、实验重叠和客户端兼容
- 依赖关系：依赖影响图、互斥冲突矩阵和降级关系
- 灰度发布：分阶段放量、环境差异、指标守护、冻结和紧急回滚（支持连带下游回滚）
- 审计与回滚：查询调整、审批、批准失效和异常事件，记录受影响用户范围
- 发布报告：查看发布明细、批量操作报告（可继续未完成项）并导出 CSV

浏览器首次打开时会自动写入示例数据。编辑、审批、灰度和回滚操作会写入 `feature-flag-release-console-v1` 对应的本地存储键。

## 发布治理规则

- **批准留痕**：发布负责人批准时必须设置冻结截止时间，系统同时定格当时的依赖运行态快照（前置依赖、互斥开关的启用状态、阶段与放量比例）和配置版本，随审计日志留存。
- **冻结窗口**：冻结没过去前，灰度阶段不能扩量，界面只允许“紧急回滚”或“补充监控”；补充监控只追加守护指标，不改变配置基线、不使批准失效。
- **批准失效联动**：前置依赖被暂停/停用、互斥开关在批准后启用，或开关配置被改动（配置版本变化）时，相关批准立即失效，运行阶段退回待复核并写入审计；启动时与每次写入前都会执行复核。
- **可恢复批量操作**：一次批量操作（批量冻结/回滚/补监控、连带回滚）拆成多个子项，逐项写开关、审计并生成操作报告。子项写入失败会保留为未完成项并可重试；操作队列保存在独立本地存储键 `feature-flag-release-console-v1-queue`，主库写入失败也不丢，重开页面会自动继续处理 pending 项。
- **失败演练**：功能开关页顶部的“演练写入失败”开关（或 `…-settings` 存储键）会让主数据库写入抛错，可用来验证未完成项保留、重试和重开恢复；关闭后点击“重试全部未完成项”即可接着处理。
