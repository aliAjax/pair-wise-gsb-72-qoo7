# 功能开关灰度发布与影响审阅平台

基于 React 的本地可运行前端工程，覆盖功能开关配置、影响评审、依赖分析、灰度时间线、冻结回滚和发布报告。业务数据由 RTK Query 端点驱动，并持久化到浏览器 `localStorage`。

## 技术栈

- React 18 + TypeScript + Vite
- MUI
- Redux Toolkit
- RTK Query
- React Router

## 启动

```bash
npm install
npm run dev
```

默认开发地址为 `http://localhost:18472`。

## 构建

```bash
npm run build
npm run preview
```

## 发布管控规则

- **批准留痕**：发布负责人批准后，审批记录会结构化留存冻结截止时间（`approval.freezeUntil`）与批准当时的依赖快照（前置 / 互斥 / 降级目标的启用状态），同时保存发布配置指纹。
- **冻结期管控**：冻结截止时间未过去前，灰度阶段不能扩量，界面上仅允许「紧急回滚」与「补监控」；补监控只追加观测指标，不改变发布配置，审批保持有效。冻结时间过去后自动解除。
- **审批失效联动**：出现以下任一情况，原审批立即失效，运行中的灰度阶段暂停并退回「待评审」，需要重新批准：
  - 前置依赖被暂停 / 关闭 / 回滚（对照批准时的依赖快照）
  - 互斥开关在批准之后才被启用
  - 批准后发布面配置（受众、地区、版本、依赖、回滚条件、灰度阶段定义）发生改动

  每次读取数据都会执行一致性扫描，失效事件写入审计日志。
- **多写操作可靠执行（outbox）**：批量回滚一次会连带修改多个开关、追加多条审计并归档发布报告。每个写入拆成独立步骤顺序提交，写入失败时未完成项保留在本地 outbox 中（含失败原因与尝试次数），可在「审计与回滚」页手动重试；页面重新打开时自动从断点续跑，已完成步骤幂等不重复落审计。审计页提供「模拟写入失败」开关用于演示。

## 工作区

- 发布概览：开关采用趋势、环境放量差异、阻断问题和待评审项
- 功能开关：按状态、环境、团队和关键字筛选，进入完整配置编辑器
- 影响评审：逐项检查规则冲突、死代码、指标缺失、实验重叠和客户端兼容；批准时选择冻结策略，已失效审批会展示失效原因与原依赖快照
- 依赖关系：依赖影响图、互斥冲突矩阵和降级关系
- 灰度发布：分阶段放量、环境差异、指标守护、冻结和紧急回滚；冻结期锁定扩量，支持补监控
- 审计与回滚：查询调整、审批、审批失效、补监控、归档报告和异常事件，支持批量回滚与 outbox 重试
- 发布报告：查看发布明细（含审批人与冻结截止时间）、批量操作归档报告并导出 CSV

浏览器首次打开时会自动写入示例数据（其中「商品智能推荐位」的审批会因其前置依赖已被冻结而在首次加载时自动失效，用于演示联动）。编辑、审批、灰度和回滚操作会写入 `feature-flag-release-console-v1` 对应的本地存储键。
